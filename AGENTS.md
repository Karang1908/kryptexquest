# Kryptex Quest repository notes

- No build or install step. Serve the root with `python3 serve.py 4173` (same as `http.server` but sends `Cache-Control: no-store`; plain `http.server` lets phones keep stale JS for minutes, which looks like "my change did nothing"), open `http://localhost:4173`. In this workspace the sandbox blocks local sockets (`PermissionError: [Errno 1] Operation not permitted`), so run the server and any browser test with the sandbox disabled.
- The Claude-in-Chrome extension may be disconnected. Headless Playwright works instead (`python3` has `playwright`; Chromium is cached). Launch with `--use-gl=swiftshader --enable-webgl --ignore-gpu-blocklist --enable-unsafe-swiftshader` or the map/model-viewer will not render. Keep scratch scripts outside the repo.
- Layout: `index.html` (shell, team screen, dialogs), `styles.css`, `admin/` (organiser console at `/admin/`, deliberately not linked or mentioned anywhere in the player UI; keep it that way), `js/` (`app.js` UI/orchestration, `map-core.js` shared map style, `world.js` camera/state/labels, `scene3d.js` three.js custom layer (explorer, beacons, grid, shadow), `demo-admin.js`, `demo-engine.js` (demo-mode game rules, mirrors migration 0004; keep them in step and re-run its Node test), `geo.js` GPS/simulator, `compass.js` phone heading, `api.js` Supabase-or-demo backend, `data.js` demo content, `config.js` public settings, `login-art.js`), `supabase/` (migrations 0001-0010, seed, `verify-photo` edge function + `judge.ts`), `admin/content.js` (content + photo review tabs), `admin/event.js` (event control tab), `board/` (public big-screen board), `scripts/loadtest.mjs`, `js/image.js`, `assets/` (two character GLBs).
- Plain ES modules, no framework or bundler. Keep that. Visual system: `theme.css` (tokens, plates, keys; shared), `styles.css` (game), `admin/admin.css` (console), `board/index.html` (inline). No emoji or unicode glyphs as icons: use `js/icons.js` (`icon('name')`, `<i data-icon>` + `hydrateIcons()`). Remote deps: MapLibre (unpkg, pinned `6.11.2`), OpenFreeMap dark style, three r160 (jsdelivr, via the import map in `index.html`; used by the game scene), model-viewer 4.3.1 (ajax.googleapis.com; now only the avatar picker), supabase-js (jsdelivr), Google Fonts.
- `CONTEXT.md` is the product and decision log. Update it when rules, data, setup or verification status change.
- The campus center is real; the four stop pins are provisional examples. Never present them as surveyed or event-ready.
- Photo verification: demo mode simulates approval (labelled). The edge function calls Ollama Cloud (Gemma) per an explicit organiser decision, but has never been run against the real API; do not claim it is verified until it has. `judge.ts` is tested with `node --experimental-strip-types`.
- SQL changes: apply `0001` then `0002` to a scratch Postgres (stub roles `anon/authenticated/service_role`, schema `auth` with `users`, `uid()`, `jwt()`) and exercise the RPCs as each role before shipping them.
- Flags in `js/data.js` and `supabase/seed.sql` are samples. Real flags go in the gitignored `supabase/seed.local.sql`, never into committed files.
- Landmines found: (1) MapLibre's remote CSS sets `#map` to `position: relative`; keep the `#map.map-canvas` override. (2) `<model-viewer>` 4.3.1 throws from its `orientation` setter (only matters for the picker now). (2b) In three.js `ShaderMaterial` GLSL, do not name variables `minor`/`major` (silently produced no output); compute distance falloff per fragment, not as a varying `length()` (it interpolates the corners). (2c) `SkeletonUtils` in three r160 is a module of functions: `import * as SkeletonUtils`, call `SkeletonUtils.clone`. (3) Do not give a MapLibre Marker's own element a CSS `transform`/animation; animate a child. (4) The game map has `interactive: false`; if you ever re-enable gestures note MapLibre `jumpTo` cancels an in-flight drag. (5) Do not re-render the stop sheet on a timer while an input may have focus (it wipes typing); it re-renders only when range flips.
- Admin console layout: `.console` is a flex column (header, optional alert bar, optional demo banner, `.a-main`). An element with its own `display` ignores the `hidden` attribute, so hidden children need `.console > [hidden] { display: none }`; a fixed grid-row layout broke the whole console once when the alert bar was added.
- Backend-path testing without a Supabase project: a scratch Postgres 14 with all migrations + `seed.sql`, plus a small Node HTTP shim that answers `/rest/v1/rpc/*`, `/auth/v1/user` and `/rest/v1/profiles` by running the RPC as the `authenticated` role (JWT payload -> `request.jwt.claims`), with Playwright serving a replacement `js/config.js` and injecting a `sb-localhost-auth-token` session. This exercised the real `api.js` Supabase code paths end to end. The shim and scripts live outside the repo; the edge function and storage are not covered.
- Locations must stay >150 m apart in demo/test data (radius 50 + up to 25 m accuracy tolerance each side), or walking into one discovers its neighbour. Gameplay rules exist twice: SQL (`supabase/migrations/0004_game_flow.sql`, the real one) and `js/demo-engine.js` (demo mode). Change both, then run the SQL scenario on a scratch Postgres and `node --experimental-strip-types` on a test of the engine.
- Test the full flow after changing quest logic (sign-in → team create/lock → map → walk → open stop → unlock → 3 puzzles → clue → next stop). Demo mode: team code `DEMO42` joins a fake team; the lobby has an "add a teammate" button, at phone width and desktop width. Check `/admin/` after touching `api.js`, `map-core.js` or the migrations. Location can be tested with the in-app simulator (menu toggle, WASD/arrows, or the pad) or Playwright `set_geolocation`.
